01 / Recommendation

Make decisions a first-class utility.

Introduce gen2::decision for the request, answer and configuration types, and Runtime::load_decider(...) returning a cloneable DecisionModel. A caller supplies text, structured JSON or conversation state and named, typed questions; gen2 validates them, evaluates a decision model, and returns typed answers plus provenance and input diagnostics.

The native implementation loads an exported full Laya ONNX graph. Rust owns preprocessing and decoding. This fits gen2’s local inference purpose while avoiding a new implementation of the encoder’s tensor operators. An HTTP adapter is an optional follow-on using the same API, useful for managed deployments; it is not the native-support completion criterion.

Definition of “supports Laya.” Rust code embedded in macOS, Windows, iOS and Android applications can load verified local bundles of the English, multilingual and typed-decisions checkpoints, evaluate all three question types offline without Python, and pass the pinned reference suite. Platform support requires a real-device run on the declared hardware/OS floor; a successful cross-compile alone does not qualify it. A documented export recipe is required. One-call download from the original Hub repository is not claimed until a compatible ONNX distribution exists.
Revision 1 review received. The supplied gen2-laya-review.json records approval of native ONNX, the decision API and local bundles; HTTP is deferred. It requests changing the restricted initial scope, with macOS, Windows, iOS and Android as minimums. Revision 2 carries those architectural decisions forward. The user subsequently authorized implementation explicitly; the full expanded release criteria below still apply.

The native implementation is present in this worktree. This document retains the release design and distinguishes implemented behavior from unverified platform and quality gates. Desktop evidence does not establish mobile support.

02 / Evidence

The model and the repository have different seams.

Laya’s actual shape

The linked repository’s English checkpoint uses ModernBERT-large plus a decision head, totals about 421M parameters, and defaults to a 512-token sequence with a 192-token head budget. Multilingual and typed-decisions variants also exist. It predicts distributions rather than generating prose. [1]

The inspected repository lists safetensors, encoder/tokenizer assets and rl_agent_config.json. A compatible ONNX bundle must be produced and validated; downloading the existing weights alone does not provide an ONNX runtime artifact. [2]

gen2’s current boundaries

Runtime owns loaded generative models. Embeddings and reranking already have separate handles. The core Backend contract requires sessions and token pullers, making it an awkward host for a decision-only model. [8]

The existing legacy Classify generates a grammar-constrained label and intentionally reports no confidence. Laya adds a different measured output contract. It should not silently replace that classifier. [9]

03 / Scope & alternatives

One capability contract across desktop and mobile.

Remove the English-only, text-only and desktop-only release boundaries. English FP32 is a useful first engineering checkpoint, but it is not the release definition. The native release covers the three published checkpoint variants, their supported input forms and decision semantics on all four required operating systems.

Required native scope

  • English, multilingual and typed-decisions bundles, selected explicitly; compatible fine-tuned bundles accepted through validated metadata, not a repository-name allowlist.
  • Text, ordered JSON and conversation states; choice, score and yes/no questions with the pinned upstream criteria and label forms.
  • Multi-state batching, explicit long-state/window options, optional routing and calibration import, with observable supported capabilities.
  • macOS, Windows, iOS and Android packaging and real-device inference; Linux remains an additional qualification target.
  • Sync/async calls, cancellation, memory admission, host-controlled residency and device/provider selection.
  • Complete probability, calibration, truncation and provenance diagnostics.

Rules for limits

  • No product-level cap merely because a request came from a phone or uses a non-English checkpoint.
  • Context and shape limits come from the actual graph, tokenizer and qualified runtime.
  • Queue, allocation and batch budgets are visible, configurable host policies. Split independent rows into microbatches where possible.
  • Report an exact unsupported feature or resource requirement; never silently alter checkpoint, precision, label order or input.
  • HTTP stays deferred per the review. A cloud service is not a substitute for native mobile support.
  • Training and agent tool execution remain separate concerns; accepting inference/calibration artifacts does not require adding a training engine.

Phase 0 records minimum OS/SDK versions and representative device classes from the host application's requirements and the pinned native runtime. Do not inherit a high OS floor from an unrelated gen2 backend. A platform cannot be marked supported by returning a fit error on every tested device: each required platform must demonstrate successful inference for each supplied checkpoint on at least one declared supported device class.

ONNX Runtime documents iOS and Android build paths; that establishes a runtime integration route, not Laya graph compatibility. The Rust binding, tokenizer C dependencies, graph and native library must all be qualified together. [11] [12] [14]

No arbitrary restrictions does not mean infinite hardware. Preserve the model's supported behavior and let applications choose policies. Device memory, actual context capacity and native kernel support are measured constraints. Any required-platform blocker produces an explicit revised proposal; it does not quietly demote mobile to a future milestone.

04 / Public API

One model, one request, typed answers.

Expose supporting types under gen2::decision; keep the crate root small. Builders validate duplicate IDs, empty labels and invalid budgets before inference. The example below is the current runnable API. Build with laya-dynamic and pass the bundle path, native-library path and optional resident-memory budget in MiB.

RUST · IMPLEMENTED NATIVE API
//! cargo run --no-default-features --features laya-dynamic --example laya_decisions -- BUNDLE ORT_LIBRARY
use gen2::{
    Runtime,
    decision::{DecisionOptions, DecisionRequest, LoadOptions, Question},
};
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut args = std::env::args().skip(1);
    let bundle = args
        .next()
        .ok_or("usage: laya_decisions BUNDLE [ORT_LIBRARY]")?;
    let native_library = args.next().map(Into::into);
    let runtime = match args.next() {
        Some(mb) => Runtime::builder()
            .resident_memory_budget_mb(mb.parse()?)
            .build()?,
        None => Runtime::new()?,
    };
    let model = runtime.load_decider(
        bundle,
        LoadOptions {
            native_library,
            ..Default::default()
        },
    )?;
    let request = DecisionRequest::text("Our invoice was charged twice. Please refund it.")
        .question(
            "team",
            Question::choice(
                "Who handles this?",
                [("billing", "Payments"), ("support", "Product issues")],
            ),
        )
        .question(
            "urgency",
            Question::score("How urgent?", ["Routine", "Soon", "Blocking"]),
        )
        .question("refund", Question::yes_no("Is a refund requested?"));
    println!(
        "{}",
        serde_json::to_string_pretty(&model.decide(request, DecisionOptions::default())?)?
    );
    model.shutdown();
    Ok(())
}
TypeCurrent contract
DecisionModelClone + Send + Sync handle; owns no copied weights. Offers decide, info, status and unload.
DecisionRequestOwned DecisionState (Text, OrderedJson or Conversation) and ordered Vec<(QuestionId, Question)>. Choice options preserve original scalar labels and insertion order; string convenience builders remain available. Normalization must detect labels whose wire keys would collide.
DecisionOptionsPer-call encode budgets, language override, deadline and cancellation. decide, decide_batch and decide_long take explicit options; Tokio adds decide_async, decide_batch_async and decide_long_async. No token stream or session mutation.
AnswerAnswer holds probabilities and calibration diagnostics; AnswerValue is the typed Choice, Score or YesNo value. Match its variant without coercion.
DecisionResultOrdered answers, manifest digest, checkpoint, configured provider/fallback policy, job-wide queue/execution microseconds, exact input rows and truncation/calibration diagnostics. Provider policy does not claim measured accelerator partition coverage.

Choice preserves the caller’s original scalar label and each option’s probability. Score returns the expected zero-based ordinal index, ordered level descriptions and probabilities. Yes/no exposes probability_yes; the wire spelling noul belongs in the Laya adapter. An application chooses its own action threshold. [5]

Precision contract. Native logits are FP32; decoding computes unrounded probabilities in FP64. A wire conversion can match upstream four-decimal formatting. Preserve answer_confidence separately from distribution_confidence (upstream confidence); expose act_probability only as an optional diagnostic. Do not label any of these a guarantee of correctness.

Native v1 applies the checkpoint’s validated per-type and per-option-count temperatures. CalibrationStatus::CheckpointProvided means those parameters were applied, not that the probabilities have been validated on a caller’s domain. Import validated calibration payloads, including option-count buckets, language overrides and histogram binning supported by the pinned reference. Validate checkpoint identity and preserve override precedence and binning bypass rules. Unknown schema versions fail explicitly. Fitting calibration parameters remains external tooling; applying them is native scope.

05 / Architecture

Keep the decision runtime out of token generation.

Runtime ownership + memory reservations surround the worker · no chat controller or KV cache required

Add an internal DecisionRuntime trait with info(), predict(validated_request) and estimated_memory(). Its factory runs on the decision worker so ONNX state stays thread-confined. The public handle sends owned commands and receives typed results. Do not extend the generative Backend trait just to return “unsupported” for every session method.

DecisionCapabilities reports supported state/question forms, long-state strategies, calibration schema, provider choices and graph envelopes. The API accepts a request unless a real capability, validation or host-budget constraint prevents execution. Generic checkpoints do not get gated by their language or repository name.

Each explicitly loaded decision model gets one worker and one ONNX session. Clones share it. Loading the same bundle twice creates two independent instances in v1 and is counted twice; transparent deduplication is deferred. The runtime maintains weak entries for observation while model handles keep worker and runtime ownership alive, avoiding an Arc cycle.

Reuse the utility pattern, not its current unbounded channel. A configurable bounded queue (suggested default eight calls per model) provides predictable admission; it is a tunable policy, not a fixed model limitation. A saturated queue returns decision_busy. Requests carry an absolute deadline checked before queuing and before execution. Tokenization caches may be added only after parity, bounded by bytes and keyed by the tokenizer/config digest and exact ordered question content.

06 / Inference contract

The graph is only half of compatibility.

  1. Validate. Accept all state and question forms declared by the pinned native adapter, with unique question IDs, valid option structure and finite numerical values. Match upstream empty-question semantics with an empty result and no forward pass. Do not copy the HTTP server’s fixed question/option/body caps into native inference. Apply configurable byte, row and allocation budgets before materializing tensors; use checked arithmetic and report which policy or graph limit was reached.
  2. Resolve configuration. Read the bundle’s tokenizer and agent config; verify the selected checkpoint’s permitted lengths. Use per-checkpoint defaults (the English reference has max_len=512 and head_max_len=192), never global constants for the family. Accept overrides within the qualified graph envelope. Record supported lengths per checkpoint/provider; theoretical encoder capacity alone does not qualify a graph.
  3. Build exact sequences. Port the pinned build_head, build_sequence, special-token handling and option clipping. Preserve leading spaces, separators, option order and removal of literal mask-token strings from user text. Serialize each state deterministically, tokenize it once, then allocate remaining state room per question. Character counts cannot substitute for this step. [6]
  4. Apply overflow policy. Default to OverflowPolicy::Reject for state truncation, lost option markers or indistinguishable option spans. An explicit AllowWithDiagnostics mode permits state cuts and option shortening with exact diagnostics, but never missing markers or collapsed options. The reference suite uses matching permissive truncation when comparing upstream behavior.
  5. Collate and run. Right-pad sequences and markers as upstream does. Feed named tensors, never positional assumptions. One row represents a question; batch shape changes are tested. Pack rows from one or multiple states into a configurable workspace budget. Split rows across forward passes when needed and restore original state/question order; never split the options of one question as though separate softmaxes were equivalent. Expose microbatch count because shape can affect floating-point results.
  6. Decode. Slice away padded options, choose the temperature bucket and any language override, apply stable softmax, and compute choice argmax, ordinal expectation or P(true). Apply validated optional confidence binning and the reference override rules without changing the underlying distribution. Apply upstream temperature sanitization bounds and record any adjustment. Preserve first-option tie behavior. Reject non-finite outputs. [7]
  7. Return diagnostics. Preserve original IDs and label order. Report input tokens across all rows, full state tokens and per-question dropped tokens, effective budgets, execution provider and checkpoint hashes.
ONNX bindingType / shapeMeaning
input_idsint64 [B, S]Token IDs for question + options + state.

ALGORITHM · DECODE AFTER INFERENCE
// Pseudocode: only real options participate in the distribution.
let temperature = effective_temperature(question_type, option_count);
let p = stable_softmax(real_logits / temperature);
let chosen = first_argmax(p);
let expected_score = sum(index * p[index]);
let probability_yes = p[1]; // noul order is false, then true
let answer_confidence = apply_optional_binning(max(p), calibration_context);
// For choice/score, handle K == 1 explicitly to avoid log(1).
let distribution_confidence = normalized_entropy_confidence(p);
// No sampling, autoregressive decode, or generated JSON parsing.

JSON and conversation support are release requirements. Use an explicit ordered JSON representation and a serializer matched against Python’s Unicode escaping, spaces, numbers and key ordering; a default sorted serde map is insufficient. Reject values outside the pinned schema rather than inventing a serialization. Preserve the reference conversation-list truncation direction. Fixtures must cover nested objects, arrays, numeric boundaries, Unicode, empty states and reordered keys.

Routing and long states

Explicit checkpoint selection is always available. An optional router ports the pinned language/routing rules, respects caller hints and reports its reason; it loads only permitted configured bundles and accounts for every resident checkpoint. It never changes checkpoint solely to hide an out-of-memory failure. Long-state handling is an explicit strategy with reported windows and aggregation; port the reference algorithm and tests, including confidence/calibration behavior, rather than inventing a generic average. Evaluate both within-window long context and multi-window aggregation independently. A caller can require a single window and receive a precise overflow result.

07 / Artifacts & provenance

Load a versioned bundle, not an arbitrary graph.

Define gen2-laya-bundle/v1, containing the complete encoder-plus-head graph, every ONNX external-data file, tokenizer assets, agent configuration, licenses and an integrity manifest. Load must fail on a missing component, bad digest, unsupported schema or incompatible tensor signature before allocating the session.

The manifest records source repository, immutable Hub revision, checkpoint/subfolder, upstream code SHA, export tool digest, ONNX opset, exact exporter/library versions, dtype, permitted sequence envelope, required tensor names/types, tokenizer IDs, file SHA-256 values and calibration identity. Export reports include dynamic-shape checks and reference comparison results. Preserve upstream and dependency notices for any adapted code or redistributed artifacts.

Reproducible export: download the pinned checkpoint in an isolated tooling environment; run the pinned upstream exporter with an explicit local source directory and output path; copy config/tokenizer assets; enumerate ONNX external data; generate digests; run graph validation and numerical comparisons; atomically promote a temporary bundle only after success. Python/PyTorch are tooling dependencies, never implicit runtime installers. Export in FP32 first. The upstream exporter already defines dynamic batch, sequence and marker dimensions with opset 18. [10]

Native runtime packaging: pin one tested runtime ABI and choose the linkage per target. Desktop supports application-linked or explicit app-local libraries. iOS uses a host-linked runtime/framework with device and simulator slices; Android packages matching NDK native libraries by ABI. Do not require arbitrary runtime library discovery on mobile. Include a small Rust-backed host example per platform, resolving library symbols and making a real prediction. Missing symbols, unsupported kernels and ABI mismatches fail with explicit diagnostics. [11] [12]

Mobile model files: the host supplies an app-private bundle directory, populated from app assets or its normal download manager. Keep ONNX external data beside the graph, avoid loading a second full copy into a language-bridge buffer, and validate before atomic installation. Distinguish bundled read-only resources, evictable caches and persistent user-downloaded models. Application lifecycle code owns downloads and storage permissions; gen2 only reads the supplied bundle. No Python, shell command or build-time model download is needed on-device.

Provider qualification: CPU is the common correctness baseline, not a permanent device restriction. Measure CoreML on Apple and eligible Android/Windows providers in phase 0; report partitioning/fallback as well as provider availability. CoreML supports configurable dynamic/static shape handling and model caching, so measure compilation and padding costs before choosing shape-specialized bundles. [13] FP16 or INT8 variants must pass precision-specific decision/calibration gates before they can be selected; silently downcasting to fit a phone is not acceptable.

Cache and distribution: The approved baseline uses local bundles on every platform. A future LayaModel::hub(...).revision(...) uses an explicit ONNX manifest and pinned files rather than GGUF discovery. Reuse gen2’s cache location conventions and progress reporting; write to a staging directory, validate hashes, then rename atomically. Include cross-process cache locking and interrupted-download recovery. Offline mode never resolves mutable branches over the network.

Size planning. The Hub lists the English safetensors file at approximately 843 MB. That is neither FP32 export size nor resident memory. A 421M-parameter FP32 weight estimate alone is about 1.68 GB (decimal), before ONNX overhead and activations. Measure peak load, inference memory and export disk usage on mobile as well as desktop; do not copy the model-card download size into gen2’s fit calculation. [1] [2]
08 / Resources & lifecycle

Predictable ownership, bounded work.

Reserve memory under RuntimeInner.admission before loading; include live decision reservations when admitting or restoring generative models. Use a reservation guard that releases on every load failure and worker teardown. Estimate weights plus a qualified workspace allowance for the maximum B/S/K shape. Reject a load whose required reservation cannot fit rather than treating an unknown graph as zero bytes.

The default residency policy keeps a decision model loaded until explicit unload or final drop. Hosts may choose an idle-release or explicit suspend policy for mobile memory pressure; the native core does not assume a permanently resident desktop process. An explicit reload() restores the same verified bundle after suspension. Automatic restoration is opt-in and reports the cold-load cost. Surface their reservations and state through a separate Runtime::decision_models() snapshot so existing generative ModelId methods retain their meaning. Dropping a temporary Runtime clone must not unload a still-owned decision handle.

SituationRequired behavior
Cancel while queuedRemove or skip the request before preprocessing; resolve it as cancelled without invoking ONNX.
Deadline during native runReturn timeout to the caller; retain ownership and reservation until native work actually ends. Attempt ONNX run termination only when qualified. Do not promise hard preemption.
Async caller drops futureSignal cancellation. The worker still owns any in-flight native call and safely discards its late result.
Explicit unloadStop new admission, cancel queued calls, finish/terminate active work safely, free the session and release the reservation. Clones then report unloaded until explicit reload (or an explicitly configured restore policy).
Last model handle dropsRequest worker shutdown without blocking the dropping thread. The worker retains its session and memory reservation until native work returns. Use explicit shutdown/shutdown_async to wait; timeout cannot safely force-free a running FFI session.
Load or worker failureRollback reservations; fail pending calls consistently. In-process native crashes remain a process-level risk, as with other native backends.

Start with one active forward pass per model and configurable ONNX threads. Benchmark contention with generative inference. Provider selection is explicit and records any permitted fallback. Keep compilation/provider caches bounded and included in memory/storage accounting.

Mobile lifecycle: expose nonblocking host hooks for memory pressure and suspension, delivered through the worker. Do not join a native thread from an iOS/Android UI callback. Request cancellation, stop admission, and free the session only after native work releases its buffers; use explicit async shutdown for app teardown. Foreground restoration verifies the same manifest and reports cold-load status. Persist no request state automatically across OS process termination. Device tests must cover repeated background/foreground cycles, pressure during inference, host callback races, thermal throttling and coexistence with another loaded model.

09 / Deferred service adapter

The same typed API across a different execution boundary.

Review decision: deferred. The following is a future adapter design, outside the revised native release. A separate backend-laya-http feature may connect to an existing Laya server. Upstream serves POST /v1/systemone, with health at /health; it does not expose an OpenAI chat endpoint. The explicit checkpoint name english selects the root checkpoint; sending convaiinnovations/laya allows upstream routing instead. [4]

RUST · PROPOSED OPTIONAL HTTP API
let decider = runtime.laya_http()
    .base_url("http://127.0.0.1:8000")
    .checkpoint(LayaCheckpoint::English)
    .connect()?;

let result = decider.decide(request).run()?;

Gen2 does not start or install the server. Use a pooled client, explicit connect/request deadlines, a bounded response body and no automatic POST retries in the first adapter. Optional bearer credentials are redacted from errors and Debug output. Disable redirects by default. Remote HTTPS is the normal deployment; plaintext beyond loopback requires an explicit setting.

Validate response IDs, answer kinds, labels, finite ranges and probability totals with tolerance for upstream decimal rounding. Record omitted fields as unknown. A strict Jev projection omits useful metadata, so requests requiring verified truncation or provenance must fail when those facts cannot be established. A 200 health response establishes liveness, not loaded-model readiness. [4]

Preserve provider-reported confidence fields verbatim, with optional metadata identifying known calibration. Do not recompute a binned answer confidence from rounded probabilities. Remote checkpoint memory is externally owned and is reported as unknown, not reserved in the native ledger. HTTP contract tests use recorded fixtures and mock responses; live parity tests pin the server and model revision.

10 / Errors & observability

Errors should explain what the caller can fix.

Add Error::Decision(DecisionError) to gen2’s existing non-exhaustive error enum, with stable codes exposed through Error::code() and explicit retry classification. Validation errors use InvalidRequest; unsupported configurations use Unsupported. A utility-specific memory error carries required and available estimates until the generative fit type is generalized; do not manufacture GGUF fit data.

12 / Validation & release

Prove fidelity before measuring speed.

Use a three-way comparison: pinned Python eager reference → Python ONNX on the exported graph → Rust on the same graph. This distinguishes export drift from Rust preprocessing or decoding drift.
