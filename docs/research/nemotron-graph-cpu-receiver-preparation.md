# Graph-only CPU saved-data receiver preparation

The graph-only Windows diagnostic needs a matching independent receiver before
native execution. The earlier receiver expects per-region thread cycle fields;
it cannot replay the new graph-only trace unchanged. The new
`graph_cpu_receiver_sources.py` derives three saved-data programs from the exact
retained thread-counter receiver sources. It never downloads an artifact or
executes a receiver, compiler, SDK or model.

All three original programs and their collection manifest have fixed byte/hash
identities. Derivation rejects a changed origin or unexpected replacement
count. Changes cover the future full source/run/job identities, graph-only
protocol/tool/reference counts, actual workflow control names, graph parser
imports and the already qualified source-composition directory layout. Every
other source/compiler/PE/supervision/output check survives. Path relocation
changes only string literal repository/cache prefixes in the Python AST.

The collector preserves the exact 59-command sequence, complete 3,425-file
source replay, 97 compiler commands, all66 SDK files, private PE/state/version
checks and all three retained graph import libraries. Its twelve graph
processes retain all144 vectors. Four complete model histories remain byte-exact
against the same 192,000-byte reference, with58 pushes and exact turns. Complete
raw wall/graph CPU traces and saved compact profiles are independently parsed.
The original integer control-drift and observer-overhead predicates remain
unchanged. Both must pass before bounded observer interpretation.

The new parser attaches one successful kernel/user CPU100ns record to each
worker graph. The collector preserves those raw records and separately totals
kernel/user CPU per logical worker across sequential graphs. Genuine zero
values remain valid. No operation/matrix CPU attribution, cycle fields,
frequency conversion, exact descheduled-time or arithmetic-only claim is
introduced. Overlapping workers are never summed into a resource share.

Publication now checks a closed expected namespace before and after writing
the manifest: only regular payloads and their expected directories are
accepted, every descriptor must match, and the existing10,000-member/1GiB
collection bounds remain enforced. Sources and all retained graph libraries
stay in the result; SDK executables and pristine archives stay on the admitted
remote receiver.

Parsed JSON records now retain the descriptor of the bytes supplied to the
parser. The collector reuses those first descriptors for provenance copying
and publication. Helper scripts, artifact-member manifests and raw metadata
reuse their earlier admitted descriptors as well; no later descriptor capture
can replace an accepted identity. All three programs reject subsequent record changes.
This fixes an inherited parse-before-binding gap without modifying historical
receiver sources.

The eight focused tests execute the actual derived graph-CPU aggregation and
publication boundary on saved-data fixtures, including zero durations and
missing/error/mixed traces, changed/missing/extra files, symlinks and unexpected
directories. The derived readers and prepublication checks also reject a
provenance record changed after parsing and before publication binding. All nine
provenance payloads are mutated separately at the actual collector binding seam.
Tests
check complete derivation outside declared edits,
literal-only relocation, identity mutations and preserved original gates.
These are receiver controls; no actual new diagnostic artifact has been
consumed or qualified.

The revised eight focused controls pass. The final complete local tool suite
passes669 tests in53.932 seconds, with eight Windows-only skips (661 executed).
These source/data controls supply no actual Windows graph, model or timing result.

`graph-cpu-receiver-sources.protocol.json` freezes the recipe and the source-only
receiver dependencies. Its native identity is deliberately unset. Before
consumption, the actual terminal native API/archive identity and passing
feature CI must be frozen; acquisition and every subprocess still need the
owned-process route. Full native acquisition stays on Linux above the original
8GiB floor. Only a separately admitted bounded result may return locally above
the original4GiB floor. A complete transport route and independent local replay
remain required before dispatch. This checkpoint does not qualify native
execution, timing, production performance or any N4/N5 release gate. Human
review remains deferred and private app transfer remains skipped.
