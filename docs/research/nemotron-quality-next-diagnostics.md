## Source audit: supported mismatches and non-explanations

**Postprocessing objective mismatch is concrete, but not a newly proven inference bug.** The native [pinned segmentation defaults](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/src/asr/diar/diar_pipeline.h) explicitly identify a CALLHOME-part1 tuned four-speaker predecessor configuration: onset/offset 0.641/0.561, padding 0.229/0.079 seconds, minimum speech 0.511 seconds and gap-fill 0.296 seconds. In contrast, the [pinned Transformers processor](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron3_diarization/processing_nemotron3_diarization.py) uses probability >0.5 without smoothing, and [NeMo's evaluation script](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/examples/speaker_tasks/diarization/neural_diarizer/e2e_diarize_speech.py) defaults to bypassing postprocessing. The measured FA increase is consistent with padding/gap filling; aggregate totals alone do not identify which operation or each interval caused it. Short minimum-duration suppression is also a source-supported hypothesis for short replies, not an established error localization. Do not tune these constants against the failed targets.

**The frozen 1.04-second geometry is already recommended.** It resolves to chunk9/right4/left0/FIFO264/cache264/update222, agreeing with the checkpoint processor/config and card. Eight output channels cover the four AMI reference speakers, and the saved hypotheses also contain four; raising a speaker limit or supplying an oracle count is not supported as a remedy. The checkpoint's internal cache-scoring threshold 0.25 is not its output speech-decision threshold: the [cache implementation](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron3_diarization/modeling_nemotron3_diarization.py) uses it while ranking cache embeddings. Do not reinterpret it as a recommendation to binarize activity at 0.25. [Pinned processor/config](https://huggingface.co/nvidia/Nemotron-3-Diarization/tree/f667ed73aee57d40cc39428eb768b4fd87a0a29e).

**“Offline” names conceal distinct execution paths.** The card's larger-context operating point is still chunked: cache264/FIFO40/chunk340/right40/update300, with 80 ms encoder frames. It is not a whole-recording single forward. The [Transformers model](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron3_diarization/modeling_nemotron3_diarization.py) implements its non-streaming call by iterating chunks with those offline configuration fields. Native [DiarModel::diarize_offline](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/src/asr/diar/diar_pipeline.cpp) instead peak-normalizes and performs one empty-cache forward. The named native `v3-offline` preset also has different resolved geometry, as documented in the [prior audit](/Users/victor/workspace/gen2-nemotron3-n0/docs/research/nemotron-quality-gaps.md). Use explicit resolved numbers in any separate comparison; selecting an “offline” name does not reproduce the published condition.

**There is no source-supported blanket normalization fix.** Pinned [NeMo process_signal](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/models/sortformer_diar_models.py) performs peak normalization only when `streaming_mode` is false. Native streaming likewise omits it; the [HF feature extractor](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron_asr_streaming/feature_extraction_nemotron_asr_streaming.py) explicitly omits Mel normalization. Its 16 kHz/128-bin, 400-sample symmetric-Hann/512-FFT, 160-hop, preemphasis0.97 and constant-edge framing match the inspected native intent/config. The misleading native argument name `reflect_left` actually causes zero left padding in [fe.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/src/asr/features/fe.cpp); it is not evidence of reflection-padding mismatch. Source resemblance is not numerical original-NeMo equivalence. Check original checkpoint dither, Mel basis, log guard, valid-frame masks and cache state in a differential diagnostic rather than assuming the converted FP32 path is a complete oracle.

**AMI channel, occupancy and session conventions remain distinct.** AMI's [signal description](https://groups.inf.ed.ac.uk/ami/corpus/signals.shtml) identifies 16 kHz channel WAVs and machine-readable participant/channel mappings; its initial segmentation was designed to aid transcription. The published references' [method](https://github.com/nttcslab-sp/diar-forced-alignment/blob/9527b7c64846fb38316a610f32e9d3466bd6d8b7/README.md) is separately forced-aligned lexical speech. The frozen crops are valid mono 16 kHz inputs with checked PCM identity. No source/evidence inspected proves a channel swap, sample-rate mismatch, global time offset or required denoising/beamforming/gain step. These must not be asserted to explain failure. A mid-meeting cold-start crop nevertheless differs from the published complete-recording context. [NeMo's base test recipe](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/examples/speaker_tasks/diarization/conf/neural_diarizer/sortformer_streaming_8spk.yaml) explicitly uses the complete annotated region without a duration cap. AOSC retains earlier speaker evidence, making a session-context effect plausible; its magnitude remains unmeasured.

## What “FP32” already means, and the missing numerical control

The retained comparison already crosses implementations: [reference.py](/Users/victor/workspace/gen2-nemotron3-n0/tools/nemotron-diarization/reference.py) loads the publisher's hash-locked `model.safetensors` through official `AutoModelForAudioFrameClassification` / `AutoProcessor`, uses `torch.float32`, `.to("cpu").eval()`, and the low-latency processor loop. This is **Hugging Face/PyTorch CPU FP32**, not native FP32. Both [N0 oracle_execution](/Users/victor/workspace/gen2-nemotron3-n0/benches/results/nemotron-diarization/apple-m4-pro/2026-10-15-n0/receipt.json) and the [frozen close FP32 metadata](/Users/victor/workspace/gen2-nemotron3-n0/benches/results/nemotron-diarization/apple-m4-pro/2026-10-16-frozen-corpus/ami-ES2004a-Mix-Headset-fp32.json) record its actual execution: torch2.8.0, Transformers commit `683b721971417b3b2c64fba9001f525607547e5a`, CPU, float32 and exact geometry. The corpus comparison uses these arrays versus native **Q8**, plus a separate native-Q8/Gen2-Q8 equality check. Thus it would be wrong to say the only existing evidence is Q8-versus-native-FP32, or that no official HF comparison has run.

The frozen CPU AMI common-frame probability MAE/max difference against HF FP32 are close0.000344/0.058883 and distant0.000725/0.077510. These are useful cross-runtime evidence, but include quantization and state accumulation; the <=2pp DER bound is not strict tensor equivalence. No native F32 GGUF run or original `.nemo` execution was found in the examined N0/frozen receipts, locked artifact list and existing comparison scripts, and no retained rejection of that route was found. This is a bounded evidence finding, not a claim about every unpublished local experiment.

**Smallest feasible independent CPU golden control:** reuse the already-working pinned HF environment and frozen PCM; do not install NeMo first. The [official feature extractor](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron_asr_streaming/feature_extraction_nemotron_asr_streaming.py) explicitly supports CPU Torch feature extraction. In a separate qualification adapter, dump its exact `input_features`, attention mask and lookahead metadata for the processor-defined first/interior/final chunks, and compare to native Mel/features on the same PCM and chunk coordinates. Keep dtype, array layout, frame masks and terminal-frame rules explicit. This needs a qualification-only native feature dump or test adapter; the public production C ABI currently provides final probabilities, not every internal tensor. A complete Python model run is already demonstrated, while this finer-grained frontend comparison remains proposed.

For a model-only/native numerical control, the pinned [converter](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/conversion/diarization.py) explicitly supports `f32` for parity work and recognizes high-resolution V3. **Its convolution kernels remain F16 even in f32 mode** because the CPU im2col path requires them. Label such a future artifact “F32-dominant with F16 convolution kernels”; do not claim an all-FP32 native oracle. The [pinned repository inventory](https://huggingface.co/api/models/nvidia/Nemotron-3-Diarization/revision/f667ed73aee57d40cc39428eb768b4fd87a0a29e?blobs=true) publishes Q8 GGUF and a `.nemo`, with no F32 GGUF. Retain source weight mapping/dtypes and output tensor-type inventory before comparing artifacts.

## Engineering and ML routes after diagnosis

An explicit production segmentation policy, selected on separate development audio and qualified with overlap/short-reply metrics, is a legitimate engineering change. Existing results show the current native CALLHOME smoothing trades missed speech for false activity under the published reference; they do not authorize selecting a new threshold/profile using these targets. A correctly pinned original-NeMo reproduction or verified frontend fix should precede claims that retraining is necessary.

If distant-room error remains with equivalent original inference and a product-appropriate reference, a licensed development corpus reflecting room reverberation, noise, overlap and turn-taking is a supported ML route. [Mind the Gap](https://arxiv.org/html/2605.15442v1) finds noise+reverberation and combining simulated/real data useful for an older offline four-speaker Sortformer, and finds artificially increasing overlap can harm diarization even when it benefits ASR. This motivates controlled development experiments; it does not demonstrate a Nemotron-3 fine-tuning recipe, justify adding reverberation to test audio, or guarantee a20% result. Keep acoustic diarization and broad transcriber-utterance occupancy as explicit distinct objectives. Further source data, training and a fresh test would be needed for stronger meeting generalization claims.
