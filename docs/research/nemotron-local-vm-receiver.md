# Proposed local macOS VM receiver for complete Pnola CLI

2026-10-17. **Lume has a plausible unattended local route; it is not yet qualified on this host.** Use an Apple restore image, a new guest disk/account and a manually unpacked publisher release. This avoids GitHub authentication/private-app upload and does not require building/signing the VM tool with the host’s keys. Remaining admission checks include actual release trust, restore compatibility/personalization, unprivileged offline-volume access and temporary VNC exposure. No VM tool/archive/OS body was downloaded, installed or executed during this research; only primary source/release metadata and an IPSW HEAD response were acquired. The live neural session was untouched.

## Restore image and resources

Avoid `--ipsw latest` as a reproducible contract. Apple’s current99,450B catalog, SHA256 `0925a0b28dc2da5342e180dac9a1911eacdae097f055c8b117882cf9b8cb2958`, lists VirtualMac2,1 with27.0.1/26A434. This catalog observation does not say the26.3 host can boot that image; Lume’s `latest` separately asks Virtualization.framework for its supported image. [Apple catalog](https://mesu.apple.com/assets/macos/com_apple_macOSIPSW/com_apple_macOSIPSW.xml), [pinned image loader](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/src/Virtualization/DarwinImageLoader.swift).

A matching-version **candidate**, not a proven compatible guest, is Apple’s [UniversalMac26.3/25D125 restore](https://updates.cdn-apple.com/2026WinterFCS/fullrestores/047-60229/6D5DBEA5-75A0-4BEF-ACC9-5ACF9B8DF6B7/UniversalMac_26.3_25D125_Restore.ipsw). Retain these as publisher metadata until the complete download is hashed. Lume checks `mostFeaturefulSupportedConfiguration`, takes image minimum CPU/RAM and creates hardware model/NVRAM; actual supported configuration and restore personalization still need successful host-specific admission. A matching filename is insufficient. Do not change host security/update configuration to overcome a failure. [Apple installation requirements](https://developer.apple.com/documentation/virtualization/installing-macos-on-a-virtual-machine), [Lume Darwin setup](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/src/VM/DarwinVM.swift).

Pinned Package.swift instead declares macOS14 minimum; host26.3 meets both documented/source OS floors. Proposed initial allocation is4CPU/8GB/100GB; image requirements can increase CPU/RAM. ## Host and guest effects

Lume’s default install script installs a user LaunchAgent/server; avoid it by manually extracting the versioned command-line archive into a task-private directory. Its release archive contains a wrapper and `lume.app`. The inspected unattended path executes host `hdiutil attach -readwrite -nomount`, `diskutil` mount/unmount, ordinary file writes/chmods inside the **guest Data volume**, then detach. It contains no host sudo, Authorization Services, AppleScript, Keychain or certificate operations. This supports an unprivileged design but does not prove that this locked host’s mount/TCC/session policy permits it without a dialog. Stop and retain a failure if permission is denied; do not escalate. Its later sudo command runs **inside the guest over SSH**, finalizing setup and preboot metadata. [Installer entry](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/scripts/install.sh), [offline patcher](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/src/Unattended/MacOSOfflineSetupPatcher.swift), [disk commands](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/src/Utils/DiskImageSession.swift), [guest finalization](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/src/Unattended/UnattendedInstaller.swift).

Unattended Tahoe creates local admin `lume/lume`, SSH, autologin and no-sleep/no-screen-lock settings; it skips Setup Assistant and verifies SSH before stopping. No cloud/Apple/GitHub account appears in this path. This is a vanilla restore **with declared provisioning changes**, not an untouched consumer setup. SIP changes are a separate optional `lume sip` command; neither SIP nor its `vncdotool` dependency is needed for this route. Preserve guest security observations and change guest credentials before private payload use; no host password or signing key is needed. [Pinned README](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/README.md), [guest commands](https://cua.ai/docs/lume/reference/cli/guest).

**Networking limitation:** unattended materialization and SSH-verification calls use `vm.run` with its default VNC-enabled policy despite `displayMode=.none`. The VNC initializer accepts port/password, not a binding address, and constructs both localhost and external-host URLs. Source therefore does not prove loopback-only exposure; temporary password-protected host VNC is part of this release’s setup. No `create --vnc disabled` override exists. Runtime `run --display none --vnc disabled` avoids the later VNC listener and automatic native-viewer clipboard path. Do not start `serve`, bridge to the LAN, or enable clipboard. NAT still permits guest egress and is **not offline isolation**; app-level network-denial/control or a separately qualified guest-only isolation step is required before claiming offline Pnola operation. [Unattended caller](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/src/Unattended/UnattendedInstaller.swift#L56-L133), [default VNC policy](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/src/VM/VM.swift#L185-L195), [VNC implementation](https://github.com/trycua/cua/blob/3350f504014c85416009a90fcb339fe556ce02fc/libs/lume/src/VNC/VNCService.swift#L73-L112), [run options](https://cua.ai/docs/lume/reference/cli/vms).
