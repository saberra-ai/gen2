## Stage A: compare filterbanks and frontend without model inference

**Bank source is a real comparison boundary.** The [native converter](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/conversion/diarization.py) copies `preprocessor.featurizer.fb`, squeezing `[1,128,257]` to `[128,257]`, into F32 GGUF tensor `preprocessor.fb`. Native `DiarModel` uses it via `set_mel_basis`. The [HF converter](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron3_diarization/convert_nemotron3_diarization_to_hf.py) explicitly drops checkpoint featurizer tensors, and the [HF extractor](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron_asr_streaming/feature_extraction_nemotron_asr_streaming.py) rebuilds a Slaney-normalized librosa bank as `feature_extractor.mel_filters`. No bank equality or inequality has yet been measured.

1. Read the already-locked Q8 GGUF as data with pinned `gguf.GGUFReader`. Select exactly one `ReaderTensor` named `preprocessor.fb`; require F32 and NumPy shape `[128,257]`, finite values and 32,896 elements. The [reader](https://github.com/ggml-org/llama.cpp/blob/bd4f514db14d87fded667787a7a963bfbaa98e89/gguf-py/gguf/gguf_reader.py) exposes GGML-order `shape` and already reversed NumPy-order `data`; use `tensor.data`, not a blind reshape of `tensor.shape`. Hash a copied contiguous little-endian F32 array and retain a flat binary/JSON descriptor. This reads no model through its inference runtime.
2. `AutoProcessor.from_pretrained(locked_assets, local_files_only=True)` supplies `processor.feature_extractor.mel_filters`, without loading the neural model. Record its contiguous F32 bytes/hash, shape and numeric difference against the native bank. Retain both unchanged. Run a preregistered bank-control matrix: each frontend with its own bank, then both with the same native bank, then both with the same HF bank. These are diagnostic frontend substitutions only; they do not replace model or baseline data. They separate bank-generation differences from FFT/window/precision differences without selecting a bank by DER.
3. The smallest native probe needs only `fe.h`, `MelSpecConfig`, `MelSpectrogramExtractor(cfg, nullptr)`, `set_mel_basis(bank,128,257)` and `compute(pcm,N,out,T,true,false)`. No BackendManager or DiarModel is needed for FE-only execution. Resolve config to sample_rate16000/n_fft512/n_mels128/window_size0.025/window_stride0.01/preemph0.97/log_zero_guard2^-24, `stft_center_window=true`, `hann_periodic=false`, and call `normalize=false`. Keep `mask_invalid_frames=false` to preserve the native raw output. Do not use the extractor's generated default bank: it is a different fallback; explicitly set the retained bank. [Native FE implementation](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/src/asr/features/fe.cpp), [configuration/API](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/src/asr/features/fe.h), [actual DiarModel FE setup](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/src/asr/diar/diar_pipeline.cpp).
4. For the first control, use a whole fixed PCM array and the HF feature extractor directly: `feature_extractor(audio,sampling_rate=16000,center=True,return_tensors="pt",device="cpu")`. Store `input_features[0]` as contiguous `[T,128]` F32 and its `[T]` attention mask. Compare the exact common **valid** rows against native `[T,128]` output; preserve all raw rows and the mask, including extra native padding. Both first samples use `y[0]=x[0]`; subsequent samples use preemphasis before STFT. Neither path should peak-normalize or apply CMVN. Do not call native `diarize_offline`, whose waveform normalization is a different path.

The native layout is frame-major: `out[t*128+m]`; HF is `[batch,time,mel]`, so batch0 is directly comparable, without transposing. The checkpoint bank is `[mel,fft_bin]`. A whole centered pass produces `floor(N/160)+1` raw native frames, while HF's valid mask retains `floor(N/160)`; compare only mask-valid rows and report any additional frame separately. Report max/mean/RMS error, location/bin of first/worst divergence and masked-row counts, with exact PCM/bank/tool hashes. Choose numerical tolerances before examining targets and do not reinterpret small floating-point differences as a quality explanation without downstream evidence.

## Stage A2: exact streaming framing and masks

Use the same loop as existing `reference.py`, taking sizes from the [processor](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron3_diarization/processing_nemotron3_diarization.py), not from arbitrary input push sizes:

| Low-latency quantity | Resolved value / rule |
| --- | --- |
| Center chunk/right context |9/4 encoder frames; subsampling8 |
| Mel frames per processor call |104; step72 |
| First raw chunk length |`(104-1)*160+400/2 = 16680` samples; center=True |
| Later raw chunk length |`104*160+400 = 17040` samples; center=False |
| Later raw start |`mel_cursor*160-512/2`; first later cursor72 gives11264 |
| Last call |`is_last_audio_chunk=True`; do not drop it when it exactly touches the endpoint |

HF processor trims feature/mask tensors to valid length; ordinary calls carry `num_lookahead_frames=4`. The final call omits that lookahead key but carries the previous speaker cache into the neural model. The [extractor](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron_asr_streaming/feature_extraction_nemotron_asr_streaming.py) adds96 zeros **after preemphasis** for an uncentered final chunk; plain raw zero padding before preemphasis would introduce a boundary impulse. Native `finish()` instead appends a geometric raw decay to make post-preemphasis padding zero. Retain these rules rather than “fixing” one to resemble the other.

Native direct `compute` emits right-padded extra rows, while `produce_new_mel_frames` releases only rows whose FFT right edge is covered. Therefore direct native FE row count/readiness does not equal the processor-trimmed chunk count. Slice common valid rows with explicit global frame coordinates; keep synthetic padding and readiness differences as metadata. Inspect [DiarStream windowing](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/src/asr/diar/diar_pipeline.cpp) when moving beyond frontend-only comparison.

### Tensor accounting and V3 numerical limits

- Native keeps encoder tensor names (including fused `encoder.layers.*.attn.w_qkv`); maps `sortformer_modules.encoder_proj`→`encoder_proj`, `subpixel_upsample`→`subpixel_upsample`, speaker head→`head`, and learned silence→`learnable_sil_emb`; writes the original bank as `preprocessor.fb`.
- HF's [mapping](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron3_diarization/convert_nemotron3_diarization_to_hf.py) splits fused QKV rows in query/key/value order and maps projection, upsampler, speaker head and `silence_embeds`. It explicitly drops the legacy auxiliary speaker/activity heads and frontend buffers. Compare source-to-output weights through these mappings, preserving source dtypes and intentional drops; neither runtime's tensor naming is an independent weight identity.
- Native `f32` still selects **F16 convolution weights**, notably the V3 subpixel upsampler, because its CPU im2col path requires them. Label the control F32-dominant/F16-conv, not all-FP32. Record every actual tensor type. The converter warns and skips unrecognized keys; require a complete reviewed emitted/skipped/unused accounting before using the artifact as a numerical control. Generic remapping may retain unused head tensors; stored extras are not proof the inference graph uses them.
- Native [run_chunk](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/src/asr/diar/sortformer_model.h) accepts Mel `[T,128]` and cache/FIFO `[frames,512]`; returns `chunk_embs` at80ms, **`native_preds` at10ms**, and `preds` averaged over eight native frames for AOSC. Compare HF `logits.sigmoid()` against the aligned native10ms predictions, not the coarse cache probabilities. Native `native_preds` covers the full active cache+FIFO+chunk+lookahead sequence; HF returned logits explicitly remove the cached prefix and lookahead. With the fixed left-context0 control, let `c` be the active cache+FIFO frame count and `q` the current non-lookahead chunk encoder-frame count. Slice native rows `[c*8:(c+q)*8]`, then clip to the same valid `num_frames` used by HF (and concatenate identically for any multiple inner chunks). The initial9/4 chunk therefore compares72 returned rows, not the full104 native rows. Alternatively instrument HF pre-crop `chunk_logits` to compare the complete teacher-forced sequence, retaining masks and final valid-frame clipping separately. Comparing unsliced native output to returned HF logits would manufacture a framing mismatch. For teacher forcing, HF cache fields include valid `embeds`, `probs`, `fifo`, `num_cache_frames`, `num_fifo_frames` and compression state; retain active prefixes rather than padded capacities. The [HF model](https://github.com/huggingface/transformers/blob/683b721971417b3b2c64fba9001f525607547e5a/src/transformers/models/nemotron3_diarization/modeling_nemotron3_diarization.py) likewise averages sigmoid probabilities, not logits, for cache scoring.
- The old upstream `dump_sortformer_reference.py` / `test_sortformer_parity.cpp` are useful staging examples, but use predecessor state/head assumptions and exclude some tails. A V3 adapter must pass the learned silence embedding into native AOSC, preserve the10ms head, and audit teacher-forced tensor/mask/shape rules. Do not invoke those old tests unexamined and call their result Nemotron-3 equivalence.

Keep Stage A, conversion accounting, teacher-forced graph/state and free-running probability results as separate evidence. Only after each comparison is defined should a new qualification process run. None changes the original DER scorer, postprocessing, gates or held-out status.
