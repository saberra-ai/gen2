Research only, 2026-10-16. No build, installation, model execution or qualification was performed for this note. Recommendations below are proposed implementation work; the current Linux native receipt remains a development result.

Runtime pin is `083861c241061562b8ec29eb06d7f6cdc3af8775`, llama/ggml pin `bd4f514db14d87fded667787a7a963bfbaa98e89`. Preserve these and the original receipt hash as package inputs.

The [actual loader report](../../benches/results/nemotron-diarization/linux-x86_64/2026-10-16-native-development/loader-dependencies.stdout.log) resolves five SDK libraries (NeMo C API, NeMo implementation, ggml, ggml-base, ggml-cpu), plus host SentencePiece, libstdc++, libgcc_s, libc, libm and the ELF loader. The first three host dependencies must either become bundled components or explicit installation requirements. For a closed **non-platform** package, bundle their exact recursive closure while retaining glibc/libm/loader as declared host components. This is an engineering recommendation, not evidence that copying those three files alone closes every dependency. Record every actual ELF edge and reject unexplained dependencies.

The smallest initial support claim is **Linux x86_64 GNU/glibc, CPU AVX2/FMA/F16C, Ubuntu 24.04 baseline**, qualified in a fresh immutable Ubuntu 24.04-derived container. A wider distribution claim requires a separately selected older build baseline and validation. Do not label this artifact musl/Alpine-compatible or generally Linux-portable.

## Proposed package implementation

1. Add a Linux-specific packager with the same trust boundary as [package_macos.py](../../tools/nemotron-diarization/package_macos.py): verify qualified input hashes before copying; resolve each alias strictly inside allowed roots; recursively enumerate ELF dependencies; package only the required libraries, stable entry path, notices and manifest. Keep headers, static archives and build tools outside the runtime payload. Models/fixtures can remain separate byte-pinned qualification inputs.
2. Capture package owner, binary/source package versions, architecture, repository/source identity, original path, real-file hash and size for SentencePiece and GCC runtimes. On this Debian-family builder use package ownership/version metadata and the exact installed copyright files, not the current website's latest version. Include source-package identity and a durable corresponding-source distribution route for redistributed GCC runtime binaries; notices alone are not a complete source-compliance plan. Do not assume the Mac Homebrew SentencePiece/Abseil/protobuf versions or notice bundle describe this Linux binary.
3. Copy DSOs into `lib/`, rewrite SDK/GGML and SentencePiece filenames/SONAMEs to a Gen2 NeMo-specific prefix, and rewrite **every** internal `DT_NEEDED` edge to that map. Decide GCC runtime sharing explicitly: for the narrow CPU package bundle exact libstdc++/libgcc_s versions, record whether their SONAMEs remain standard, and qualify coexistence. Blindly giving a second C++ runtime private names is not proof of safe exception/runtime ownership. Retain C ABI ownership: allocate/free opaque handles within their originating runtime.
4. Remove absolute build paths and set relative loader paths on all DSOs and helper executables. For consistency with upstream, choose DT_RPATH (`$ORIGIN` for sibling DSOs and `$ORIGIN/../lib` for helpers), and verify no DT_RUNPATH or build-directory entries remain. A per-DSO DT_RUNPATH design can also relocate but has different precedence and must be a deliberate policy. The loader documents that RUNPATH is direct-dependency-only, RPATH applies to descendants, and `$ORIGIN` is the object's directory. [Linux loader contract](https://man7.org/linux/man-pages/man8/ld.so.8.html). Use a pinned packaging tool and record original/final hashes; [patchelf](https://github.com/NixOS/patchelf) supports SONAME, needed-name and rpath rewriting. Inspect the resulting ELF rather than trusting command success.
5. Rewrite/rebuild the independent probe's RPATH too: [platform_native.py](../../tools/nemotron-diarization/platform_native.py:163) currently embeds the absolute SDK directory. Package transformation must produce a new final hash without replacing its original provenance.
6. Record required `GLIBC_*`, `GLIBCXX_*`, `CXXABI_*` and `GCC_*` symbol versions for **all** payload ELF files, including bundled runtimes and qualification executables. Reject requirements outside the declared baseline; record ELF class, machine, interpreter and ISA assumptions. A bundled newer libstdc++ can itself require newer glibc, so it does not lower the platform floor. GCC documents the [versioned C++ ABI](https://gcc.gnu.org/onlinedocs/libstdc++/manual/abi.html). Static libstdc++/libgcc is not a packaging shortcut: GCC calls out shared-libgcc requirements when exceptions cross shared-library boundaries. [GCC link options](https://gcc.gnu.org/onlinedocs/gcc/Link-Options.html).

## File identity, licenses and delivery

The current [receipt writer](../../tools/nemotron-diarization/platform_native.py:235) omits symlinks and modes. Extend package identity using `lstat`: regular file SHA256/size/mode, directory mode, symlink target/type. Only allow relative links resolving within the package; reject escaping/absolute links, devices, unexpected hardlinks and setuid/setgid bits. Either preserve each SDK SONAME alias or flatten deliberately to private real files and declare the stable entry alias. An unresolved alias must fail verification, not disappear from the manifest. Verify the exact allowed file set after extraction, including executable permission on helpers. Use tar/gzip with deterministic ordering/ownership/time and actual mode/symlink preservation; publish the archive as an opaque CI artifact. Python's [tarfile metadata and extraction filters](https://docs.python.org/3.12/library/tarfile.html) provide a reference for safe handling; extraction checks do not replace manifest verification.

Licenses are component-specific. Gen2 is MIT in [Cargo.toml](../../Cargo.toml). NeMo is [Apache-2.0](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/LICENSE); retain its NOTICE and full [third-party notices](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/THIRD_PARTY_NOTICES.md), including MIT ggml and Apache NVIDIA patches. SentencePiece's top-level license is [Apache-2.0](https://github.com/google/sentencepiece/blob/master/LICENSE), but capture the actual shipped version's bundled notices too. GCC's [libstdc++ licensing page](https://gcc.gnu.org/onlinedocs/libstdc++/manual/license.html) specifies GPLv3 plus Runtime Library Exception 3.1; use the actual GCC package copyright/license set for both libstdc++ and libgcc_s rather than labeling the bundle MIT/Apache. glibc remains a host dependency in the proposed archive; a distributed container image has its own additional OS-library/source/license inventory. Models remain separately licensed OpenMDW-1.1 at the locked revision; including model or corpus bytes requires their notices/attributions as well. Packaging tools need build provenance; do not include their executables accidentally.

An initial metadata-preservation implementation now exists in
[sdk_archive.py](../../tools/nemotron-diarization/sdk_archive.py): successful Linux
native development runs emit a deterministic SDK tar and complete lstat
inventory, rejecting escaping aliases and unsupported metadata. Model-free
roundtrip/determinism and alias-rejection tests pass. Actual native CI archive
creation/roundtrip is still pending, and this snapshot does not implement the
runtime dependency closure or relocation gates above.

## Private GGML and chat gate

Private names prevent accidental same-SONAME reuse but are insufficient evidence of ELF symbol isolation. The [current Unix loader](../../src/diarization/ffi.rs:80) uses `Library::new`, with no separate namespace requested. ELF lookup can resolve imports to the main executable or previously global objects before the newly loaded object's definitions; RTLD_LOCAL alone is not complete isolation. [dlopen/dlmopen specification](https://man7.org/linux/man-pages/man3/dlopen.3.html).

Before closing this gate, inspect dynamic exports and test actual Gen2 chat plus diarization in both initialization orders, with repeated/concurrent activity and shutdown. Capture loaded real paths/hashes and relevant GGML symbol bindings, and compare the same smoke outputs/lifecycle invariants. CPU-only diarization should not load the chat GGML implementation. If evidence shows interposition, stop the packaging claim and make a separately reviewed isolation change: hidden/prefixed native symbols, a glibc-specific `dlmopen` namespace with C ABI lifecycle coverage, or process isolation. Do not silently add RTLD_DEEPBIND or claim renamed DSOs solve every symbol collision. Package relocation tests alone cannot close this gate.

## Fresh-container qualification to implement

Use a digest-pinned runtime image with the declared baseline glibc, **without** compiler, SDK, development packages or SentencePiece. For strongest closure detection, construct the small test image from its declared OS runtime components and inventory them, rather than accepting whatever a general CI runner installed. No `apt` or network work during qualification. Docker's [none network](https://docs.docker.com/engine/network/drivers/none/) retains only loopback; use `--network none`, read-only asset/package mounts and a separate writable result location. [Docker run options](https://docs.docker.com/reference/cli/docker/container/run/).

Run the following in that future environment, with empty LD_LIBRARY_PATH/LD_PRELOAD/LD_AUDIT and no original SDK path mounted:

- Extract the delivered tarball into a relocated directory containing spaces/non-ASCII characters; validate manifest, aliases, modes and all ELF metadata before loading.
- Resolve every dependency to either package files or the exact allowlisted host glibc family; fail missing libraries, system SentencePiece/GCC fallback and source/build paths. Record actual loaded paths as well as static edges. Qualification tooling can be separate from the released runtime.
- Run the already-frozen native/public stream comparison and lifecycle/error/cancellation/reset tests using only the extracted package, prebuilt Gen2 binaries and locked assets. Preserve outputs/hashes, commands, exit codes, timings and container digest. No new quality thresholds or target tuning.
- Run chat/diar coexistence above in a prebuilt binary containing the actual chat backend. Repeat on the oldest claimed baseline and a newer representative baseline; keep CPU requirements explicit. A container does not emulate an older CPU or provide a separate kernel, so it is not proof of every Linux host/ISA.
- Prove no loadable fallback by executing from outside the original checkout/cache and testing a deliberately missing bundled required DSO. Loader failure is expected, not host substitution.

Only then publish a new receipt binding package/archive SHA256, source/build/packager/tool provenance, component versions/licenses, full filesystem manifest, glibc/ISA policy and these container/coexistence results. Preserve the current development receipt. Until those runs exist, runtime packaging, fresh-machine relocation and Linux chat isolation remain open gates.


## Addendum: exact Ubuntu source bundles and notice provenance

Read-only review of the new `package_linux.py` source acquisition, 2026-10-16. No APT source acquisition, builds or models were run. The design is defensible engineering provenance, subject to the CI checks below; it is not a general legal-compliance determination.

- **Correct identity and inventory.** `dpkg-query` explicitly provides `source:Package` and `source:Version`; these are preferable to inferring source from the binary package or compiler executable. APT documents exact `source=version` selection and download-only acquisition without unpacking; `--only-source` makes the intent explicit. The `.dsc` specification defines its SHA256/size/name list as the files constituting that source package. Checking source/version, every listed file, and the exact resulting directory set is a useful fail-closed check. [dpkg-query fields](https://manpages.debian.org/bookworm/dpkg/dpkg-query.1.en.html), [Ubuntu Noble apt-get source semantics](https://manpages.ubuntu.com/manpages/noble/man8/apt-get.8.html), [.dsc format](https://manpages.debian.org/bookworm/dpkg-dev/dsc.5.en.html).
- **GCC source and documentation indirection are expected.** Published Noble amd64 [libstdc++6](https://packages.ubuntu.com/noble/libstdc++6) and [libgcc-s1](https://packages.ubuntu.com/noble/libgcc-s1) metadata identify `gcc-14` as their source and an exact-version dependency on `gcc-14-base`; do not fetch `gcc-13` merely because it compiled the SDK. These web versions are examples, not evidence of the actual CI installation. Following `/usr/share/doc/<binary>` to the real copyright file and requiring its owning package's source name/version to match is appropriate. Debian policy expressly permits documentation-directory symlinks between packages from the same source and version; it does not require the notice-owning binary package to equal the runtime binary package. [Documentation policy](https://www.debian.org/doc/debian-policy/ch-docs.html#copyright-information).
- **Concrete notice follow-up.** The published [SentencePiece 0.2.0-1build1 copyright](https://changelogs.ubuntu.com/changelogs/pool/universe/s/sentencepiece/sentencepiece_0.2.0-1build1/copyright) identifies `debian/*` as GPL-2+ and refers to `/usr/share/common-licenses/GPL-2`. Since the proposed artifact includes the entire Debian source bundle, it also includes those packaging files. Copying only GPL-3 does not preserve the referenced GPL-2 text. Include and hash the common-license texts referenced by the actual copyright files (at minimum this GPL-2 reference; a clearly named Apache-2.0 text is useful too), or explicitly map each reference to an included full text. This is not a claim that the SentencePiece runtime becomes GPL-2. GCC's [actual example copyright](https://changelogs.ubuntu.com/changelogs/pool/main/g/gcc-14/gcc-14_14.2.0-4ubuntu2~24.04.1/copyright) includes the Runtime Library Exception and broader source-tree notices; preserve it verbatim rather than deriving a single license for the entire source archive. Some full license texts also live inside the source archives; record their availability instead of assuming an installed-host absolute path survives redistribution.
- **APT authentication is a precondition to record.** `.dsc` hash checks establish internal bundle consistency, not repository authenticity by themselves. APT's normal archive trust chain authenticates repository metadata, while configuration can disable that protection. Record source definitions/pockets/components, Signed-By/keyring identity, relevant APT authentication settings, successful update/acquisition logs and downloaded identities; reject insecure/trusted override configurations. Do not describe parsing a clearsigned `.dsc` as independently verifying its signature. [APT security model and overrides](https://manpages.debian.org/bookworm/apt/apt-secure.8.en.html). Enable matching `deb-src` for each binary origin, including updates/security and SentencePiece's universe component. If the exact installed source version is no longer indexed, fail rather than silently choosing latest; freeze the acquired bundle before the runner image or indexes move.
- **Path ownership and trust limits.** `dpkg-query -S` searches its recorded pathname database. Canonicalizing `/lib` to `/usr/lib` before querying can therefore fail on installations whose package records retain the alternate spelling; a controlled fallback can query both aliases, then require one package identity and the same resolved file/hash. This is a fail-closed compatibility consideration, not an observed failure in this run: current published Noble amd64 [libgcc-s1 file list](https://packages.ubuntu.com/noble/amd64/libgcc-s1/filelist) and [libstdc++6 file list](https://packages.ubuntu.com/noble/amd64/libstdc++6/filelist) already record `/usr/lib`. Retain the architecture-qualified binary package identity for queries. Ownership/version metadata also does not prove an installed file is unmodified official package content; the trusted CI installation and its logs remain an assumption unless compared with the exact authenticated `.deb` payload. These bundles provide source provenance, not reproducible-build proof.

CI must still exercise the real installed package versions, copyright resolution, authenticated exact-source acquisition and package-manifest verification before this part of the gate closes. The source bundle increases artifact size substantially for GCC; deduplicating a shared exact source/version between both GCC runtime components is appropriate, while treating two different versions as interchangeable is not.
