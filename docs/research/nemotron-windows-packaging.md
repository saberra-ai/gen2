## Search directories are not DLL namespaces

[Gen2's Windows load](../../src/diarization/ffi.rs:65) canonicalizes the entry path and uses `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_DEFAULT_DIRS`, without changing process PATH. This searches the entry DLL's directory for dependencies, plus application directory, added user directories and System32. A tighter future package policy could use DLL_LOAD_DIR plus SYSTEM32, with every non-system dependency next to the entry. This is an optional reviewed loader change, not an implemented property. [LoadLibraryEx flags](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibraryexw).

**Neither variant establishes isolation from chat GGML.** Microsoft documents that dependency resolution can reuse a loaded module with the same module name irrespective of its folder, and dependencies are searched by module name even when the entry used an absolute path. [Windows DLL search order](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order). Separate directories and full-path entry loading therefore do not close the duplicate `ggml*.dll` gate.

Proposed in-process route: give all five NeMo-owned DLLs unique Gen2 NeMo basenames and rewrite/relink every internal import to those names, retaining public C ABI function exports. Prefer an auditable build-only naming overlay/relink if convenient; alternatively use a pinned PE-aware import editor. Microsoft's [DetourBinaryEditImports](https://github.com/microsoft/Detours/wiki/DetourBinaryEditImports) explicitly permits changing imported file names, showing that this is feasible without changing inference algorithms. This is not evidence that a chosen editor handles every delay/bound-import case: inspect those tables and reject unsupported forms, or rebuild. Do not blindly replace byte strings or overwrite a short name with a longer prefix. Do not insert Detours byways or runtime hooks just to rename dependencies. Record original/final hashes and all transformed tables; modified images need any intended signing performed after transformation.

Keep Microsoft DLLs unmodified. Confirm there are no ordinary/delay imports, forwarded exports or dynamic native load names left pointing to generic NeMo/GGML filenames. GGML_BACKEND_DL OFF reduces plugin-loading scope in this recorded build but is not proof that all dynamic loads are absent. Test chat and diarization in both load orders, concurrently, and through repeated shutdown/reinitialization. Enumerate loaded modules and full paths/hashes with [EnumProcessModules](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-enumprocessmodules) and [GetModuleFileNameExW](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getmodulefilenameexw); capture at stable points and retry snapshots if the module list changes. If private imports cannot be demonstrated, process isolation is the defensible fallback, requiring a separately reviewed interface.

## Microsoft runtimes, license evidence and other notices

Choose one deployment contract explicitly. A self-contained plugin directory can carry the permitted individual VC DLLs unchanged and qualify the existing directory-scoped loader; this avoids an installation prerequisite but makes this package responsible for runtime updates. Alternatively distribute a pinned offline x64 VC Redistributable installer as a prerequisite and qualify its installation/logs; Microsoft recommends central deployment for servicing. Do not claim the latter archive runs on a machine with no prerequisite installed. Microsoft's [redistribution guidance](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files?view=msvc-170) allows individual application-local deployment and describes installer switches and servicing tradeoffs. A plugin directory is verified through the explicit loader policy here, rather than assuming it is the executable's application-local folder.

Microsoft's [VS 2022 REDIST list](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution) permits licensed users to distribute specified files from `VC\redist` with their program, subject to the applicable terms, and requires unmodified files; `debug_nonredist` is excluded. Record exact source redist paths, file/product versions, SHA256 and signature/signer evidence, applicable license version/edition and distribution basis. Copy the applicable runtime license/associated notices from the actual licensed distribution into the package's Microsoft component directory; the SDK's Apache/MIT notices do not license Microsoft DLLs. The public [runtime terms](https://visualstudio.microsoft.com/license-terms/vs2022-cruntime/) and [VS edition terms](https://visualstudio.microsoft.com/license-terms/vs2022-ga-proenterprise/) are linked by Microsoft's license directory, but the actual entitled distribution's terms must be retained; this note does not establish the distributor's entitlement or interpret every license condition. The recorded 65-file SDK has no Microsoft license/notice component, so that provenance remains a packaging gate.

The cache's `MSVC_REDIST_DIR` is `14.44.35112`; the failed probe command used compiler tools `14.44.35207`. Do not infer compatibility or incompatibility solely by comparing those directory suffixes. Capture actual binary/tool versions and verify the Microsoft-supported runtime/toolchain combination. Microsoft requires a matching target architecture and a redistributable at least as recent as the build tools; rolling latest links must be frozen to exact bytes if used later. [Supported runtime/version guidance](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170).

For a declared Windows 11/Server 2022 target, retain UCRT/API-set/system DLLs as OS dependencies, not arbitrary copied SDK/System32 payload. Microsoft identifies UCRT as an OS component on Windows 10+ and Server 2016+; on Windows 10/11 the system UCRT wins over an application-local copy. [UCRT deployment](https://learn.microsoft.com/en-us/cpp/windows/universal-crt-deployment?view=msvc-170). API-set names require an explicit OS-contract policy rather than treating every absent on-disk `api-ms-*` name as a missing bundled DLL.

Preserve the installed NeMo LICENSE, NOTICE, THIRD_PARTY_NOTICES, MIT ggml license, and vcpkg SentencePiece/Abseil/protobuf/utf8-range license files. [Pinned NeMo license installation](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/CMakeLists.txt) copies installed vcpkg copyrights but not package/version build records. Include vcpkg resolved status/SPDX metadata, triplet, baseline, port/source hashes and patches, and audit bundled/header-only attribution against those sources. The [pinned manifest](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/083861c241061562b8ec29eb06d7f6cdc3af8775/vcpkg.json) uses baseline `9e593bb18ea69cc5095e012465dcd675a822ed0d`; its [SentencePiece port](https://github.com/microsoft/vcpkg/blob/9e593bb18ea69cc5095e012465dcd675a822ed0d/ports/sentencepiece/portfile.cmake) requires static Windows linkage and package-provided Abseil/protobuf. Models/fixtures remain separate licensed, byte-pinned assets; shipping them adds their existing notice/attribution requirements.

## Actual next gates

1. Wait for the separate native/public real-model retry and lifecycle result; do not promote the failed probe receipt. Bind the final package to the successful exact SDK receipt and build-only overlay hashes.
2. Implement bounded PE dependency discovery and allowlisted OS contracts; package the final private native closure plus unchanged, qualified VC components/notices. Manifest exact file set, relative paths, hashes, sizes, PE AMD64 machine and transforms. Reject unexpected reparse points/case-insensitive duplicate paths; no production dependence on build PATH, Visual Studio, vcpkg, Python, import libraries or original checkout. Validate archive extraction and relocation into a path with spaces/non-ASCII characters.
3. Qualify on a fresh Windows VM or Sandbox with no VS/build tools/third-party dependency installs. Pin and record OS edition/build/update/image identity and actual CPU capabilities; Server 2022 same-host success does not establish Windows 11 support. For Sandbox, explicitly set networking disabled, readonly input mapped folders and vGPU disabled; defaults are insufficient. Microsoft documents these controls in [Sandbox configuration](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file). Use a separate writable evidence folder and start from a fresh instance; this note has not established Sandbox availability on the CI host.
4. Execute prebuilt native/public comparison, reset/cancellation/error/lifecycle checks and real chat coexistence using extracted artifacts and frozen local assets only. Record all actually loaded DLL paths/versions/hashes, including centrally reused VC runtimes. Test absent packaged native DLLs fail instead of falling back to another installation. A preinstalled system VC runtime can mask missing bundled VC files: prove actual loaded paths and also exercise the intentionally chosen central-runtime contract, if supported.
5. Issue a new receipt only after offline relocation, closure, loader isolation and lifecycle gates pass. Keep source/model quality gates separately visible; a Windows package test cannot convert the existing quality failures into passes.

These are proposed steps. There is no clean Windows runtime package or clean-machine qualification evidence established by this investigation.
