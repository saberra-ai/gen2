## Valid-length and final-token chain in218d0b4

1. The [AudioToMelSpectrogramPreprocessor](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/modules/audio_preprocessing.py) delegates to `FilterbankFeatures`. Config omits `exact_pad`, so its defaultfalse centers a512-point STFT with constant padding. [FilterbankFeatures.get_seq_len, lines436–440](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/parts/preprocessing/features.py#L436-L440) computes `floor((N+512-512)/160) = floor(N/160)` without STFT's extra `+1`. Its [forward, lines562–641](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/parts/preprocessing/features.py#L562-L641) masks physical rows at/after that valid length to `pad_value` and may pad physical width to a multiple of16. Dither is applied only in training mode. Raw tensor width and valid length are distinct.
2. [Sortformer.forward, lines909–916](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/models/sortformer_diar_models.py#L909-L916) physically crops processed mel to `processed_signal_length.max()` before `forward_streaming`. `process_signal` omits peak normalization in streaming mode. Batch-one crop width is111for17872samples and12000for1920000samples; extra STFT and pad-to16 rows do not enter the streaming chunk loader.
3. [SortformerModules.streaming_feat_loader, lines300–319](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/modules/sortformer_modules.py#L300-L319) advances9×8=72mel rows and clamps center/right to physical valid width. It supplies per-row valid lengths. The final calls thus contain39mel rows from cursor72 for calibration and48from11952for120s, with zero right offset. Unlike HF's raw per-chunk extractor, this `forward` route extracts the whole waveform once and chunks its features; no per-chunk96-sample audio padding operation is needed here.
4. [FeatureStacking, lines50–86](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/parts/submodules/subsampling.py#L50-L86) pads physical feature time to a multiple of8, reshapes to1024features and projects; valid encoder length becomes `ceil(valid_mel/8)`. Final counts are39→40physical slots→5valid tokens, and48→48slots→6valid tokens. An incomplete group is a valid token with zero feature-padding slots, not a wholly invalid token.
5. [forward_streaming_step, lines1376–1421](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/models/sortformer_diar_models.py#L1376-L1421) concatenates active cache/FIFO embeddings and lengths, then calls `frontend_encoder(..., bypass_pre_encode=True)`. The [TransformerEncoder padding mask](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/modules/transformer_encoder.py#L114-L121) admits keys with `kv_idx < length[b]`; full-attention mode uses that valid-length domain. This is key masking, not a claim of a separate false query mask on each feature-padding slot.
6. [forward_infer, lines660–672](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/models/sortformer_diar_models.py#L660-L672) upsamples encoder outputs and repeats the encoder-valid mask eight times. The final incomplete group can therefore produce eight physical10ms predictions. The streaming step slices cache/context, while [forward_streaming, lines1219–1226](https://github.com/NVIDIA-NeMo/Speech/blob/218d0b443441b7d8aa1c832f47df310f186cf0a4/nemo/collections/asr/models/sortformer_diar_models.py#L1219-L1226) crops concatenated predictions/logits back to the original valid mel length. Top-level forward also masks final output lengths. This yields111/12000rows, not112/12001.

These semantics agree with the HF final-length/stack counts in the separate [partial-tail source note](/Users/victor/workspace/gen2-nemotron3-n0/docs/research/nemotron-partial-tail-control.md); they do not establish feature/probability equality. Native's additional row remains a concrete difference from **both audited official paths**. A source mismatch can now be described precisely, while a defect/cause/fix claim still requires the separately frozen controls.
